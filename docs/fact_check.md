# Claim and Related-Work Ledger

Last checked: **2026-08-05**

This ledger separates external facts from synthetic observations and research
hypotheses. A simulator result must not be presented as a hardware result. A related
idea must not be presented as novel without a direct comparison to the cited work.

## Status vocabulary

- `CONFIRMED`: directly supported by a paper, official implementation, or official
  documentation.
- `RELATED_WORK`: substantially overlapping prior work exists.
- `HYPOTHESIS`: a claim this project is designed to test.
- `SIMULATION_RESULT`: observed only under the current deterministic synthetic model.
- `BOUNDARY_CASE`: a reproducible limit or failure region that constrains applicability.
- `REGRESSION_CONFIRMED`: a previously recorded result reproduced after a code change;
  this does not promote its evidence level beyond simulation or calibration.
- `CALIBRATED_RESULT`: reproduced with measured traces or real hardware.
- `HARDWARE_RESULT`: directly measured on stated hardware; synthetic routing or model
  abstractions must still be named explicitly.
- `UNVERIFIED`: evidence is currently missing or too indirect.

## Approved project wording

> This project studies native position-parallel refinement and critical-path-aware
> execution for expert-parallel MoE models.

The optimization target is therefore not `tokens per expert` alone:

```text
useful finalized work
---------------------
native refinement work + distributed critical-path time
```

subject to explicit accounting for unique experts, expert-weight bytes, all-to-all
bytes, recomputed or non-finalizing updates, queueing, KV movement, and scheduler
overhead.
